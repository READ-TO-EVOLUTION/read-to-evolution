# 本の感想プラットフォーム
## 勉強コース／非勉強コース ＋ 冊数 × データ量制御
### Cursor用 統合仕様書（2026-01-xx）

## 0. 前提とゴール

本アプリには以下の2系統が存在する。

* **非勉強コース**（通常の本の感想・レビュー・ギフト等）
* **勉強コース**（試験・学習向けの問題／解説／復習ログ）

本仕様書の目的は：

* 勉強コースを追加しても **非勉強コースは引き続き使える**
* 勉強コースを **無理なく価格設定・コスト管理できる**
* 初見ユーザー・外部テスターでも **迷わず使えるUX** を担保する

---

## 1. コースの関係性（重要）

✅ **勉強コースに登録しても…**

* 非勉強コースは **すべて引き続き利用可能**
* ギフト機能／レビュー／書籍管理などは制限しない

👉 勉強コースは **追加オプション** という位置づけ  
👉 **排他的ではない**

---

## 2. 勉強コースの基本構造

### 2-1. 学習単位（冊）

「1冊」＝ ユーザーが定義する **1学習単位**

* 1科目
* 1書籍
* 1試験範囲 など

### 2-2. 登録できるデータ種別

**すべて 保存・制限対象**

| 種別 | 内容 |
|------|------|
| 問題 | 問題画像＋OCRテキスト |
| 解説 | 解説画像＋OCRテキスト |
| 基本書 | 教科書・条文・参考書画像＋OCR |

※ OCRは **ユーザー端末で実行**  
※ サーバーは「画像＋テキストを保存」

---

## 3. 復習フロー（勉強コース特有）

### 復習時の「解説選択」は二段階方式

#### 第1段階：登録済み解説から選択

* そのユーザーが **過去に登録した解説のみ**
* 複数選択肢から選ぶ

#### 第2段階：ワード検索補助

* キーワード入力
* そのワードを含む解説文だけを選択可能
* OCRテキストを検索対象にする

### 解説を間違えた場合の挙動

選択した解説に紐づく

* 問題画像
* 該当ページ（基本書）

を **参照表示してOK**

👉 学習体験として「戻れる」設計は推奨  
👉 強制ではなく補助表示

---

## 4. 段階式設計とコスト観点

問題・解説・基本書すべてを段階式にしても？

* **段階数そのものはコストに直結しない**

コストを決めるのは：

* 保存画像数
* OCRテキスト量
* AI解析（※今回は未実装）

👉 よって **段階式UXはOK**

---

## 5. 勉強コース 価格プラン（確定）

### 採用するプラン

| プラン | 価格 |
|--------|------|
| 3冊 | 450円 |
| 5冊 | 700円 |
| 10冊 | 1,400円 |
| 20冊 | 2,600円 |

* 30冊以上の常設プランは **作らない**
* 20冊プランで **実質60冊相当の使い方**になる可能性はあるが、
  * 裏でデータ制御するため **計算上は問題なし**

---

## 6. 冊数 × データ量 制御（重要）

### 6-1. 1冊あたりのデータ上限

#### 通常ライン（警告なし）

| 種別 | 上限 |
|------|------|
| 問題画像 | 300枚 |
| 解説画像 | 400枚 |
| 基本書画像 | 500枚 |
| **合計** | **1,200枚 / 冊** |

#### 拡張ライン（警告あり）

| 種別 | 最大 |
|------|------|
| 問題 | 500枚 |
| 解説 | 500枚 |
| 基本書 | 500枚 |
| **合計** | **1,500枚 / 冊（絶対上限）** |

### 6-2. UI挙動

* **〜1,200枚**：通常表示
* **1,200枚超**：
  * ⚠️ 注意表示
  * 整理を促す文言
* **1,500枚到達**：
  * 追加登録不可
  * 「別冊として登録してください」

### 6-3. サーバー側制御（必須）

**フロントだけでなく APIで必ず制限**

擬似コード：

```typescript
if (volume.imageCountTotal >= 1500) {
  throw new Error("VOLUME_IMAGE_LIMIT_EXCEEDED")
}
```

---

## 7. OCR・保存方式

* **OCR処理**：ユーザー端末
* **サーバー保存**：
  * 画像
  * OCR済みテキスト

OCRテキストは：

* 復習時の検索
* 解説候補絞り込み

に使用

---

## 8. UI/UX 方針（今日決まった点）

* **初見ユーザー向けガイドを常設**
* **用語補足**（ギフト／成果計測／冊 など）を明示
* 「制限」ではなく  
  👉 **整理・学習効率向上として伝える**

---

## 9. 非勉強コースとの切り分け

* **冊数制限・データ制限は 勉強コースのみ**
* **非勉強コース**（感想・ギフト等）は**無制限**

---

## 10. 設計思想（Cursor向け）

* **表の課金軸**：冊数
* **裏の安全装置**：データ量制御
* **UXは「禁止」より「理解・整理」**
